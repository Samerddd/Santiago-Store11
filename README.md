# Santiago Store

واجهة متجر عربية RTL مبنية بـ React وVite، مصممة لتُنشر كـ static app على Vercel. لوحة الإدارة تفتح عبر `/admin`، والأقسام هي هوديز وأحذية رياضية وإكسسوارات والكلرات والقمصان. الأسعار بالشيكل، وخيارات التوصيل في الواجهة: الضفة ١١، القدس ٣٠، الداخل ٥٠ شيكلاً. مخطط PostgreSQL وسياسات RLS لـ Supabase موجودة في `supabase/schema.sql`.

## التشغيل المحلي

1. ثبّت Node.js 20 أو أحدث.
2. نفّذ `npm install` ثم `npm run dev`.
3. انسخ `.env.example` إلى `.env.local` وأضف بيانات مشروع Supabase.

## ربط Supabase

1. أنشئ مشروعاً في Supabase، ثم نفّذ `supabase/schema.sql` من SQL Editor.
2. ينشئ مخطط SQL bucket باسم `product-images` للصور العامة للمنتجات ويقصر الرفع والتعديل والحذف على المديرين عبر Storage policies. إذا كان مشروع Supabase أُعدّ بالمخطط السابق، شغّل `supabase/security_hardening.sql` لترقية السياسات القائمة وإزالة السماح بإدخال الطلبات مباشرة.
3. عيّن `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` في `.env.local` محلياً وفي Vercel Project Settings > Environment Variables. مفتاح anon مخصص للواجهة ويجب أن يبقى مقيداً بسياسات RLS.
4. **لا تضع `service_role` key أو أي سر إداري في الواجهة أو في متغير يبدأ بـ `VITE_`.** لا يمكن إخفاء ملفات JavaScript اللازمة لتشغيل الموقع عن زوار المتجر؛ إعداد البناء لا ينشر source maps، وVercel لا يقدّم ملفات المصدر خارج `dist`.
5. أنشئ مستخدم المدير في Supabase Auth ببريد وكلمة مرور تختارهما. ثم شغّل في SQL Editor:

   ```sql
   update public.profiles
   set role = 'admin'
   where id = (select id from auth.users where email = 'ADMIN_EMAIL');
   ```

   استبدل `ADMIN_EMAIL` ببريد المدير. لوحة `/admin` تتحقق من جلسة Supabase ودور `admin` في قاعدة البيانات؛ لم تعد هناك كلمة مرور ثابتة داخل كود الموقع.
6. استخدم Supabase Edge Functions أو RPC موثوقاً لعمليات الدفع والطلبات. سياسات SQL تمنع العميل من إدخال طلبات أو بنود طلب مباشرة بأسعار يختارها بنفسه.
7. من إعدادات Supabase Auth، فعّل تأكيد البريد، وسياسة كلمات مرور قوية، وحدود المحاولات، وفعّل MFA لحساب المدير. أعد تشغيل `supabase/schema.sql` على مشروع جديد قبل إضافة المنتجات.

## نشر Vercel

اربط مستودع Git بـ Vercel؛ إعدادات البناء الافتراضية مناسبة (`npm run build` ومجلد `dist`). يحتوي `vercel.json` على rewrite لدعم التطبيق، وأضف متغيرات Supabase قبل النشر.

اجعل مستودع المصدر خاصاً، ولا تضع مفاتيح `service_role` أو كلمات المرور في Git أو في متغيرات `VITE_*`. متغيرات `VITE_*` تُضمّن في ملفات المتصفح وتُعد علنية؛ المفتاح المسموح للواجهة هو anon key فقط مع RLS.

## الحالة الحالية

تتضمن الواجهة الرئيسية والمنتجات والبحث والفلاتر والتفاصيل والسلة والمفضلة وخطوات الطلب والحساب والطلبات ولوحة الإدارة. إعداد Supabase مطلوب لتسجيل الدخول الآمن وإثبات صلاحية المدير؛ بيانات المنتجات والطلبات الحالية في الواجهة ما زالت محلية، لذا لا تنشرها كمتجر تشغيلي قبل توصيل CRUD والطلبات إلى الجداول/Edge Functions. نموذج الدفع بالبطاقة للعرض فقط ولا يجمع بيانات البطاقة ولا ينفذ تحصيلاً. يضبط `vercel.json` سياسة CSP ورؤوس الأمان، ويبني Vite ملفات الإنتاج دون source maps.
